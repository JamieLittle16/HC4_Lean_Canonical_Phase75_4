# HC4 proof architecture

This document explains the **live proof routes** in the cumulative Lean development. It is intentionally organized by mathematical role rather than by chronology or filename length.

The exhaustive file/declaration list is generated by `tools/generate_proof_inventory.py`; this document answers the more important question: **which route should a proof use, and which apparently similar infrastructure belongs to a different route?**

## 1. The top-level shape

The current unrestricted front door is built around a contradiction to a hypothetical distinct exact gradient collision for a four-variable polynomial with Hessian determinant one.

At a high level:

```text
F with hessianDeterminant F = 1
        +
distinct p,q with mvGradientMap F p = mvGradientMap F q
        |
        v
canonical collision normalization / automatic nonlinear degree cap
        |
        v
zero-defect collision entry
        |
        v
positive canonical rank-one Rees re-entry
        |
        v
rank-one state
        |
        v
A18.4.109 finite raw-defect termination trace
        |
        v
actual reached rank-three state, repair provenance retained
        |
        +------------------------------+
        |                              |
        | positive actual raw defect   | zero actual raw defect
        v                              v
positive Rees test / low layer    concrete zero strict-low terminal
        |                              |
        v                              v
success = ordinary trace restart   singular maximal top face
failure = concrete low layer            |
                                       v
                              balance-free Newton boundary
                                       |
                                       v
                              cross-facet / first-nonfacet /
                              codimension-two / confinement
                                       |
                                       v
                                  local contradiction
```

The important design principle is that **the global recursion is already finished**. New final-assembly work should not introduce a second clock, a second termination relation, or another recursive trace.

## 2. Unrestricted collision entry

The public reduction is in the A19 front-door modules, especially:

- `HC4/Valuation/AdaptiveAlignedSmithCanonicalCollisionAutoDegree.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalZeroDefectCollisionEntry.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalHC4Reduction.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalHC4ReachableTerminalReduction.lean`

`AdaptiveAlignedSmithCanonicalHC4Reduction` proves determinant-one gradient injectivity from impossibility of normalized presented terminals. The later reachable-terminal version is the more precise interface for final assembly because it retains the fact that the terminal really arose from the canonical rank-one route and therefore still satisfies

```lean
state.repair = rankOneRepairState 0
```

Do not replace the reachable-terminal front door by a stronger arbitrary-terminal hypothesis unless a genuinely generic theorem needs it. The repair equality is useful provenance, not disposable bookkeeping.

## 3. The only global termination mechanism

### 3.1 A18.4.109: `AdaptiveAlignedSmithCanonicalRankOneTerminationTrace`

File:

- `HC4/Valuation/AdaptiveAlignedSmithCanonicalRankOneTerminationTrace.lean`

This is the canonical global termination object. It has two constructors:

```text
terminal geometry
restart progress rawDefect_lt repair_eq tail
```

A restart stores all three facts needed for the recursive call:

1. actual `AdaptiveAlignedSmithCanonicalGlobalMacroProgress`;
2. strict decrease of the natural `rawDefect`;
3. unchanged repair metadata.

The definition recurses **only on `source.rawDefect : ℕ`**.

### 3.2 A18.5.75: structural trace collapse

File:

- `HC4/Valuation/AdaptiveAlignedSmithCanonicalRankOneTraceCollapse.lean`

Once the reached terminal is impossible, the finite trace is consumed by ordinary induction. The strict-decrease certificates are not re-proved and no second measure is used.

**Rule:** any proposed final proof that invents another well-founded relation should first explain why it cannot be represented as an ordinary `restart` edge in this existing trace.

## 4. Positive Rees success belongs inside the existing trace

The important correction in A19.34b is encoded in:

- `HC4/Valuation/AdaptiveAlignedSmithCanonicalPositiveTransverseReesFrontier.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalPositiveTransverseReesSourceProgress.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalRankOneReesTraceReduction.lean`

A successful positive transverse Rees coefficient bound supplies exactly what an A18.4.109 restart needs: global macro progress, a strict raw-defect drop, and preserved repair state. Therefore it is inserted into the existing rank-one trace **at the actual unramified trace state**.

This ordering matters. Testing only after a normalized terminal introduces a pure ramified presentation and can obscure comparison with the original source raw defect. The Rees-reduced trace avoids that error.

`AdaptiveAlignedSmithCanonicalRankOneReesReducedTrace` therefore ends in exactly one of:

- raw defect zero; or
- a concrete `CanonicalPositiveTransverseReesLowLayer` on the actual reached state.

There is no residual “successful Rees re-entry” branch once this reduction is used.

## 5. Terminal carriers and RationalRigidity

The rank-three terminal route is split into interfaces rather than one monolithic theorem.

Important files include:

- `HC4/Valuation/AdaptiveAlignedSmithCanonicalTerminalSupportFrontier.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalTerminalRigidityData.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalTerminalSingularCarrier.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalTerminalRankThreeFirstContact.lean`
- `HC4/Valuation/AdaptiveAlignedSmithCanonicalTerminalImpossible.lean`
- `HC4/RationalRigidity/RankThreeAffineTwoFixedImpossible.lean`
- the broader `HC4/RationalRigidity/RankThree*.lean` family.

`AdaptiveAlignedSmithCanonicalTerminalImpossible` is an adapter: it turns the actual singular terminal carrier plus genuine balanced supported rank-three line certificates into the already-proved RationalRigidity contradiction. It deliberately does **not** identify every affine first-contact line with the older integral finite-segment model; that would reintroduce divisibility assumptions that later affine infrastructure was designed to remove.

This is a recurring architectural rule: preserve the exact carrier and exact geometry you have. Do not silently coerce a newer, weaker-assumption carrier into an older, stronger-assumption model merely because their conclusions look similar.

## 8. Zero-clock strict-low chain: A19.49–A19.70

This is the current detailed local route and is worth knowing in order. Each file is intentionally a small, provenance-preserving adapter.

### A19.49 — concrete residual normal forms

`AdaptiveAlignedSmithCanonicalZeroStrictLowResidualNormalForm.lean`

An actual strict-low Smith exponent gives one of three concrete two-endpoint factorisations:

- pure longitudinal: derivative has an `X (X - 1)` factor;
- low-negative-first: coefficient polynomial has an `X (X - 1)` factor;
- low-negative-second: symmetric factorisation.

### A19.50 — exact mixed-degree seed

`AdaptiveAlignedSmithCanonicalZeroStrictLowMixedDegree.lean`

The **same actual strict-low exponent** also carries exact same-Smith-exponent mixed ordinary-degree support and first longitudinal departure. The important point is identity of the exponent and carrier, not merely existence of analogous data.

### A19.51 — zero-clock packet

`AdaptiveAlignedSmithCanonicalZeroStrictLowZeroClockPacket.lean`

Pure ramified presentation preserves literal zero raw defect. This bundles:

- presented raw defect zero;
- blocker defect zero;
- residual normal form;
- exact mixedness;
- first longitudinal departure.

### A19.52 — first-contact Hessian geometry

`AdaptiveAlignedSmithCanonicalZeroStrictLowFirstContactHessian.lean`

The right-recentered special fibre has vanishing linear coefficients. The retained later longitudinal support therefore triggers the existing first-contact Hessian lemma and yields a genuine nonzero diagonal-or-mixed Hessian event.

### A19.53 — producer-free local terminal

`AdaptiveAlignedSmithCanonicalRankOneReesZeroStrictLowTerminal.lean`

The live global/local split no longer asks for an abstract first-contact producer. It stores the actual zero-clock state, actual presented blocker, and actual represented strict-low exponent.

### A19.54 — retain the genuine singular top face

`AdaptiveAlignedSmithCanonicalZeroStrictLowSingularTerminal.lean`

The strict-low packet is paired with the genuine nonzero maximal ordinary top face whose Hessian determinant is zero. This is the singular polynomial carrier used by the unconditional Newton boundary machinery.

### A19.55 — balance-free boundary frontier

`AdaptiveAlignedSmithCanonicalZeroStrictLowBoundaryFrontier.lean`

The singular nonlinear top face exposes an actual coordinate-boundary exponent, split into:

- rank three on a coordinate facet; or
- codimension two.

No torus balance is used.

### A19.56 — literal support strata

`AdaptiveAlignedSmithCanonicalZeroStrictLowBoundaryStrata.lean`

The abstract boundary equations are converted into actual nonempty `zeroCoordinateSupport` slices of the top face. This is what later finite-support exposure consumes.

### A19.57 — recentered outside support

`AdaptiveAlignedSmithCanonicalZeroStrictLowRecenteredOutsideSupport.lean`

The retained first longitudinal departure gives literal positive-coordinate support on the **right-recentered represented special fibre**. It does not claim that this witness lies on the maximal top face.

This distinction is important: top-face support and recentered-source support are different carriers.

### A19.58 — rank-three top-face facet split

`AdaptiveAlignedSmithCanonicalZeroStrictLowRankThreeFacetSplit.lean`

For a rank-three top-face boundary exponent:

- if positive omitted-coordinate support exists on the same top face, construct `CrossFacetInitialData` immediately;
- otherwise every top-face exponent has zero omitted coordinate, so the whole top face is confined to that facet.

### A19.59 — source hypotheses for first non-facet contact

`AdaptiveAlignedSmithCanonicalZeroStrictLowFirstNonfacetSource.lean`

Exports from the represented special fibre:

- nonlinear degree bound by the selected top degree;
- polynomial Monge–Ampere equation;
- `TopDegreeOnFacet` when the maximal face is confined.

### A19.60 — exact source trichotomy

`AdaptiveAlignedSmithCanonicalZeroStrictLowRankThreeSourceSplit.lean`

The rank-three branch is:

1. direct cross-facet top face; or
2. top face confined but lower nonlinear source support leaves the facet; or
3. all nonlinear source support is confined.

### A19.61 / A19.63 — source support from residual factorisations

- `AdaptiveAlignedSmithCanonicalZeroStrictLowResidualSupport.lean`
- `AdaptiveAlignedSmithCanonicalZeroStrictLowPureResidualSupport.lean`

The low-negative and pure-longitudinal residual factorisations are converted into actual nonlinear monomials on the unrecentered represented source.

### A19.62 / A19.64 — confinement restrictions

- `AdaptiveAlignedSmithCanonicalZeroStrictLowConfinementFacetElimination.lean`
- `AdaptiveAlignedSmithCanonicalZeroStrictLowConfinementPatternSplit.lean`

Actual source monomials eliminate impossible confinement facets. In particular complete strict-low nonlinear confinement cannot occur on the marked `.qs` facet. The low-negative cases have sharper surviving-facet lists.

### A19.65 — low-degree tameness is exhaustive

`HC4/Newton/FirstNonfacetLowDegreeSquareSplit.lean`

For a coordinate facet:

```text
LowDegreeTameAtFacet
    OR
literal supported quadratic square in the omitted coordinate.
```

Failure of tameness should not be treated as a vague residual branch; it is an explicit degree-two monomial.

### A19.66 — genuine lower first-contact cross-facet carrier

`AdaptiveAlignedSmithCanonicalZeroStrictLowFirstNonfacetCrossFacet.lean`

In the tame lower-outside-support branch, the generic first-nonfacet selector is run on the actual represented special fibre. The result stores an honest exact cross-facet carrier, zero Hessian determinant, nonlinear support, and the exact first-contact equation.

It can then be refined to the balance-free `CrossFacetRayData` from A19.67.

### A19.67 — balance-free finite-support ray

`HC4/Newton/FiniteSupportCrossFacetRay.lean`

Three successive finite-support exposures replace the unavailable torus-balance equation and force an affine support ray.

### A19.68 — outside boundary exponent

Two layers:

- generic: `HC4/Newton/PositiveCoordinateSingularBoundaryVertex.lean`;
- terminal adapter: `AdaptiveAlignedSmithCanonicalZeroStrictLowBalanceFreeRayBoundary.lean`.

The exposed boundary exponent remains positive in the old omitted coordinate. Therefore, if it is rank three, its new facet must differ from the old facet.

### A19.69 — genuine boundary transition

`AdaptiveAlignedSmithCanonicalZeroStrictLowCrossFacetBoundaryTransition.lean`

Both direct and lower first-contact cross-facet carriers yield an actual nonlinear boundary exponent outside the starting facet. The result is:

- rank three on a **different** facet; or
- codimension two.

### A19.70 — exact rank-three residual reduction

`AdaptiveAlignedSmithCanonicalZeroStrictLowRankThreeBoundaryReduction.lean`

The rank-three zero strict-low branch is reduced to four provenance-honest possibilities:

1. boundary transition on the actual top face;
2. boundary transition on an explicitly retained lower first-contact carrier;
3. literal omitted-coordinate quadratic square;
4. complete nonlinear source confinement to the starting facet.

The lower carrier is intentionally retained rather than transported back to the top face.

## 9. Carrier/provenance rules

Many past dead ends came from proving a correct fact on the wrong carrier. Treat these as distinct objects unless an explicit theorem transports between them:

- original source polynomial;
- normalized/recentered source;
- polynomial family;
- family special fibre;
- presented/ramified family;
- canonical blocker endpoint raw special fibre;
- longitudinally right-recentered special fibre;
- maximal ordinary top face;
- exact first-contact face;
- cross-facet face;
- lower first-nonfacet carrier;
- final finite-support ray.

A support witness on one of these is **not automatically** support on another. An equality or subset theorem must be named and used.

Likewise distinguish:

- source raw defect;
- presented raw defect;
- endpoint defect;
- raw-defect decrease on an actual trace edge.

Pure ramification gives precise multiplication laws; it does not make arbitrary cross-scale inequalities well founded.

## 10. What not to rebuild

Before writing new infrastructure, search for existing versions of:

- coordinate support filters and finite-support max/min selectors;
- weighted initial-form coefficient/support lemmas;
- Hessian singularity preservation through initial forms;
- boundary / rank-three / codimension-two predicates;
- first-contact weights and contact equations;
- exact Smith-exponent mixed-degree data;
- longitudinal coefficient polynomials and `X(X-1)` factorisations;
- right-recentering identities and zero-linear-jet lemmas;
- positive Rees coefficient bounds / low-layer alternatives;
- global macro progress and raw-defect restart certificates;
- rank-three affine-line reconstruction and RationalRigidity terminal contradictions.

See `CANONICAL_OWNERS.md` for the current owners.

## 11. Current frontier vs historical branches

The repository intentionally retains older routes because they are proved and reusable. Their presence does not make them the preferred live route.

In particular:

- older balanced rank-three/cross-facet affine-line infrastructure remains valid;
- the unrestricted zero-clock branch should prefer the newer balance-free finite-support path;
- old phase-status Markdown files describe historical proof states, not current missing-lemma lists;
- old reduction structures may have more residual fields than the newer Rees-reduced route; use the strongest current reduction compatible with the hypotheses you actually possess.

When deciding what remains, follow the imports and the newest live reduction theorem, not a historical TODO list.
